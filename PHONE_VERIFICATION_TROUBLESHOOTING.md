# Phone Verification Troubleshooting Guide

## Overview
This guide helps troubleshoot Firebase Phone Authentication issues in the customer registration system.

## Prerequisites Checklist

### 1. Firebase Console Setup
- [ ] Go to Firebase Console → Your Project
- [ ] Navigate to **Authentication** → **Sign-in method**
- [ ] Ensure **Phone** is **ENABLED**
- [ ] For development/testing:
  - [ ] Add test phone numbers in **Phone numbers for testing**
  - [ ] Format: **+971501234567** (UAE example)
  - [ ] Generate and copy the test verification code

### 2. Firebase Billing
- [ ] Firebase Phone Authentication requires billing enabled
- [ ] Go to **Project Settings** → **Billing**
- [ ] Ensure billing is enabled and payment method is valid

### 3. reCAPTCHA Configuration
- [ ] Go to **Authentication** → **Settings** (gear icon)
- [ ] Under **reCAPTCHA Enterprise integration**, ensure it's configured
- [ ] For development: reCAPTCHA v3 invisible token should work

## Common Issues and Solutions

### Issue 1: "Failed to send SMS" immediately

**Cause:** Firebase Phone Authentication not enabled or misconfigured

**Solution:**
1. Open Firebase Console
2. Go to Authentication → Sign-in method
3. Check that "Phone" provider is ENABLED (blue toggle)
4. If not enabled, click on Phone and enable it

### Issue 2: "Invalid reCAPTCHA token" or reCAPTCHA errors

**Cause:** reCAPTCHA not properly initialized or missing configuration

**Solution:**
1. Verify the `<div id="recaptcha-admin"></div>` exists in the dialog
2. Check browser console for reCAPTCHA errors
3. In development, Firebase should auto-initialize reCAPTCHA v3
4. Check that no other reCAPTCHA instances are conflicting

### Issue 3: "Auth/operation-not-allowed" error

**Cause:** Phone authentication method disabled in Firebase

**Solution:**
1. Go to Firebase Console → Authentication → Sign-in method
2. Click on Phone provider
3. Toggle it ON if it's OFF
4. Save changes

### Issue 4: Phone number not accepted or timeout

**Cause:** Invalid phone number format or network issues

**Solution:**
1. Ensure phone number format is correct:
   - Valid: +971501234567 (with country code)
   - Invalid: 0501234567 (without country code)
2. The app auto-formats numbers starting with 0 to +971
3. Check internet connection
4. Try a different phone number

### Issue 5: "Too many requests" error

**Cause:** Rate limiting by Firebase

**Solution:**
1. Wait 1-5 minutes before trying again
2. For testing, use test phone numbers with test verification codes
3. Check Firebase limits in console

## Testing with Test Phone Numbers

### For Development/Testing:

1. Go to **Firebase Console** → **Authentication** → **Sign-in method** → **Phone**
2. Under **Phone numbers for testing**, click **Add**
3. Enter test phone number (e.g., +971501234567)
4. Firebase will generate a test verification code
5. Use this code in the dialog for testing

### Example:
- Test Phone: +971501234567
- Test Code: 123456 (generated by Firebase)

## Debug Logging

The application includes detailed logging. Open browser console (F12) and look for messages starting with `[v0]`:

```
[v0] Starting phone verification for: 0501234567
[v0] Formatted phone: +971501234567
[v0] Recaptcha element found: true
[v0] Creating new RecaptchaVerifier...
[v0] RecaptchaVerifier created successfully
[v0] Calling signInWithPhoneNumber...
```

### If you see errors:
- RecaptchaVerifier created successfully → reCAPTCHA OK
- Auth/invalid-phone-number → Phone format issue
- Auth/operation-not-allowed → Phone auth not enabled
- Auth/too-many-requests → Rate limit hit

## Browser Requirements

- Modern browser (Chrome, Firefox, Safari, Edge)
- JavaScript enabled
- Cookies enabled
- Pop-ups allowed (for some reCAPTCHA versions)

## Network Requirements

- HTTPS connection (or localhost for development)
- No strict ad/tracker blocking that might block reCAPTCHA
- No VPN that blocks SMS delivery

## Production Checklist

- [ ] Phone authentication enabled
- [ ] Billing enabled on Firebase
- [ ] reCAPTCHA configured
- [ ] Test with real phone number
- [ ] Email verification working
- [ ] Database connections tested
